# One current pre-visit communication purpose

Follow-ups now derives introduction/confirmation from one timing decision per visit: first contact well ahead gets an introduction; tomorrow or within 24 hours gets combined introduction/confirmation; an already-introduced or returning customer gets confirmation only. Confirmed reminders do not repeat. Cancelled/concluded/started visits do not generate pre-visit drafts. Tomorrow uses UK calendar fields, including clock changes. Historical completed/outcome visits and existing confirmed outbound history inform returning-customer context; the current visit, no-shows and adviser non-attendance are not prior-meeting evidence.

Legacy saved introduction, combined and day-before task keys match one current purpose without a schema migration. The latest effective reminder/snooze is retained; superseded active copies retain their task records and a source-resolution event/reason. The current card uses the current template/type, not an old saved task's stage. Saved pre-visit reminders close at visit start, with `previsit_window_closed` provenance, not sent evidence. Existing deadline archiving records missed obligations on inbox refresh.

Review buttons in Follow-ups re-read current booking/timing before choosing a template. Existing edited message drafts are never silently rewritten or deleted; changed-purpose drafts remain available through saved messages and existing stale-context protections. No automatic send or provider invocation is added.

Verification: full npm suite; unit timing scenarios (far/tomorrow/same-day/returning/sent/cancelled/started/DST), legacy task consolidation, latest snooze and expiry. Synthetic Chromium and WebKit journeys cover stale inbox action, combined preview, edited draft, duplicate task history, reload and expiry/missed archive with no sent flags. Existing clear-action, event-resolution, quiet-booking and saved/stale draft journeys retained. Boundaries/next: this release unifies Follow-ups entry points only. Other explicit Messages/visit communication entry points retain their prior template selection. Today's outcome logging, service issues, manual tasks, aftercare, quotes and payment purposes remain separate. Refresh-driven, not a background notification service. Existing confirmed customer-level outbound history remains the legacy fallback for prior contact; it is not proof of visit-specific date agreement. Call/agreement outcomes and purpose-specific history need a subsequent slice. Physical iPhone acceptance and production runtime monitoring remain unverified.
