## Change and boundaries

New Visit → Scan customer details now carries the form's current date. Scan shows
the selected-day fallback and returns to that dated Add form. An undated result
shows this date in the editable result fields; a date provided by the document
is not replaced by the planning day. Starting a general scan clears old context.
Route date context is strictly validated and is never claimed to be an OCR result.

OCR-unavailable manual entry now exposes a visit date, defaulting to that selected
day (otherwise today). A cleared/invalid date is rejected before customer/visit
creation. “Save Customer & Visit” makes the existing booking side effect explicit.
The edited scan button's decorative icon is hidden from its accessible name.

Existing document date parsing, stale-year normalisation, type selection,
duplicate checks, explicit human Save and09:00 default are retained. No new AI,
transcription, provider, send, database-schema or earnings rule changes. Existing
scan/new-visit instant constructors still use the device timezone; this slice's
save tests use Europe/London and do **not** certify foreign-device wall-clock
creation times. That broader scheduling-time consistency remains separate work.

Appointments67/OCR24/cache172; DB49 unchanged. Only isolated release checkout
runtime is edited; original dirty changes remain preserved.
